# Zgent v1.1 统一验收

使用有初始提交、可丢弃的 Git 仓库。确认登录、真实模型的可用性和计费来源，再在用户项目开始试用。记录各运行时与客户端版本。`/web` 签发的链接、私有配置和 API 凭据留在本机。

| 个人版现场验收 | 验收动作 |
| --- | --- |
| 终端入口 | 在测试仓库执行 `zgent`，确认首次无需写配置，Daemon 按需启动，项目自动登记。用 `/project` 切换仓库并回到旧会话。输入 `/web` 打开控制台，再次使用同一短效链接应无法兑换新会话。 |
| AGY 主控与快照 | 登录真实 AGY，在第一条消息前从 `/model` 选择。用新建和忽略文件验证读范围，再说「按这个方案改」。核对同一轮任务的基线相同。用 `/worker` 切换后继续原对话，再用 `/resume` 验证真实 Codex 跨模型续做。 |
| ACP 用量 | 用真实账号发送连续两轮，对照 ACP 原始响应和持久化用量，核对按轮或累计的口径，以及 `inputTokens` 是否包含 `cachedReadTokens`，再验收缓存占比。 |
| 审批与结果 | 用真实 Codex 触发一次原生审批，挂起时用 `/why` 询问主控，确认审批随后仍可在 TUI 处理。检查命令证据、任务状态和中文汇报。验收 `/diff`、`/apply`、`/discard`，并确认保留手工改过的候选。 |

| 场景 | 验收动作 |
| --- | --- |
| 官方 MCP 双入口 | 分别从 Antigravity App、Claude Code 与同一个 Daemon 用账号实际派活，查询状态、追加说明、等待和显式取消。检查项目读取和任务控制范围，以及显式授权后的跨客户端控制。 |
| Codex Sol 和 Astra | 在控制台确认两个档案出现在真实模型目录，各运行一项任务。核对运行时模型、产物、取消和原生审批。用已停止的任务上下文建新任务，核对新 worktree 和独立权限。 |
| AGY ACP 主会话 | 新建 AGY 会话，在发送任何消息之前确认出现 ACP 模型列表并选择模型。发送首条消息，观察流式输出并通过 MCP 派活。验证同一提供方切换模型，以及停止回答和取消任务组可以独立操作。 |
| Claude 主会话与 worker | 使用专用 API 或云身份验证 Opus、Fable 的实际可用性。分别验证主控、Claude worker、人工问题、受限命令、追加消息、取消、用量证据和计费来源。切换 Google/Claude 主控时核对可见摘要和任务引用。 |
| 工作区与恢复 | 显式纳入已跟踪修改，核对未跟踪排除清单和独立候选。真实写入途中重启 Daemon，检查未知执行保留且不会重派。确认子进程退出后，用控制台人工对账。清理干净工作区后核对候选分支和产物仍在。 |
| 宿主与事件回放 | 在实际支持 MCP Apps 的宿主中打开任务卡片、读取结果、跳转到控制台审批。需要给浏览器建立会话时先在 TUI 输入 `/web`。分别断开 SSE 和刷新浏览器，核对重连后的任务状态和历史游标。 |
| Linux 真机 | 用目标发行版、实际用户与 Codex 权限验证原生沙箱、工作区隔离、进程组停止、重启对账。不同发行版的用户命名空间或 sandbox 配置以目标机器为准。 |
| 日常试用 | 在用户选定项目持续使用一周，记录任务质量、证据可用性、审批频率、失败和恢复情况。 |

本地可重复检查与真实账号验收分开记录。独立 Gemini API 自动化和需要宿主额外能力的原生 MCP Tasks、宿主人机授权，按设计中相应需求和能力条件单独纳入。
