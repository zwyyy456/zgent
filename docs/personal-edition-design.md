# Zgent 个人版设计方案

在项目目录运行 `zgent`，由主控读取当前代码并一起确认方案。用户说「按这个方案改」后，主控把任务派给默认 worker，在独立 Git worktree 执行。任务完成后，主控用中文汇报实际改动和验证结果，由用户决定应用或丢弃。

## 1. 入口与本地连接

| 入口 | 连接方式 | 用途 |
| --- | --- | --- |
| TUI | 通过 `owner.sock` 使用 HTTP，复用现有路由和 SSE | `zgent [path]` 按需启动 Daemon，直接进入会话。人工审批在终端内完成 |
| Web | `/web` 通过 `owner.sock` 签发短效、一次性的跳转链接 | 打开已登录的浏览器，查看大 Diff 或历史任务。浏览器写操作校验 Origin 和 CSRF |
| 官方 Antigravity App、Claude Code | 通过 loopback HTTP `/mcp` 连接，各用自己的凭据 | 派活、查询、查看结果，默认各自控制自己发起的任务 |

Daemon 拿到 `daemon.lock` 后再清理残留 socket，并按字节检查 macOS 的 socket 路径长度。TUI 通过 `owner.sock` 获得本地用户身份，免凭据和 CSRF。退出 TUI 后，已发起的 worker 可以继续。验收时验证主控和 worker 的工具均无法连接 `owner.sock`。

首次运行 `zgent` 时，程序探测本机 `codex`、已有 `~/.codex` 和 `agy`，内置 `sol`、`astra`、`review`、`agy-main` 默认档案。配置文件用于覆盖默认值。缺少 CLI、登录或模型时，界面显示对应档案的不可用原因。`zgent daemon status` 和 `zgent daemon stop` 可在自动启动跑通后补齐。

## 2. 项目与工作区基线

- **打开项目。** `zgent` 从当前路径识别 Git 工作区根目录和分支，按规范化后的 Git 公共目录在 SQLite 中查找或登记项目，加入最近项目，并向两个官方 MCP 客户端开放派活和查询。同一仓库的子目录和关联 worktree 归到同一项目，会话和任务记录实际使用的工作区根目录。同名仓库各有稳定且适合路径使用的 `project_id`，目录名用于显示，沿用已经登记的 ID。不在 Git 仓库时，或输入 `/project` 时，可以选择最近项目或输入本地路径。
- **按项目保留历史。** 一个项目可以有多个主会话。切回项目后，可以继续已有会话，也可以新开会话，查阅该项目的任务、Diff、验证记录和应用状态，或查看仍保留的任务 worktree。
- **统一主控读取范围和 TUI 快照。** 两者都包含全部已跟踪文件，以及未被项目 `.gitignore` 规则忽略的新文件。主控可以读取文件、搜索代码和查看 Git 状态、Diff、历史。已跟踪的文件仍在范围内，即使后来写进了 `.gitignore`。
- **按轮次固定基线。** TUI 默认采用工作区快照，`/base head` 改用干净的 `HEAD`。轮次开始时记录基线模式，Daemon 在该轮首次接受内部 `delegate_task` 时才解析 `HEAD` 或拍快照，并持久化基线 OID。同轮任务复用该 OID，纯聊天轮次无需拍快照。`/diff` 显示任务相对其基线的增量，两个官方 MCP 入口默认使用 `HEAD`。
- **每个任务使用独立 worktree。** Daemon 按项目选择编号最小的空闲路径，例如 `worktrees/<project_id>-1`，从本次基线为新任务创建 worktree 和独立分支。运行中、待审阅或清理失败的 worktree 继续占用原路径，并行任务使用其他编号。只有在 Git 清理成功且工作区记录标记为 `removed` 后，路径才可复用。SQLite 的路径唯一约束只覆盖尚未清理的记录，历史任务和 Diff 继续按任务 ID 查询。

## 3. 对话、调度与审批

- **主控流式对话。** TUI 顶部显示项目路径、分支、主控模型和默认实现 worker。AGY 可在独立的会话目录中运行，通过只读工具访问当前项目，恢复对话时使用 Zgent 保存的 ACP 会话 ID。AGY ACP 在首条消息前提供实际可选的模型，`/model` 用于切换。
- **固定指令在前，动态内容在后。** Zgent 为主控和 worker 组织提示时，把通用指令放在开头，并保持同一工具集的定义顺序稳定，以便复用相同的提示前缀。本次目标、基线模式和默认 worker 写入主控当轮消息。派活后将已固定的基线提交和快照信息写入 worker 任务书。最新 Git 状态、Diff 和验证结果随任务书或工具结果追加。
- **记录主控用量。** 每次 `session/prompt` 返回时，`agy.ts` 将 `usage` 中上报的 `inputTokens`、`cachedReadTokens` 和 `outputTokens` 回传给会话层，按原值写入对应轮次的 `main_turns.usage_json`。主控的缓存输入占比按同一统计范围内的缓存读取 token 数除以总输入 token 数计算。缺少计数或分母为零时，占比显示为未知。
- **按用户意图派活。** 「先看看」进入只读讨论。「按这个方案改」直接派给默认 worker。新主会话从配置读取默认 worker，例如 `sol · gpt-6.2-sol`。「这次用 Astra」只覆盖当前任务组，`/worker` 只调整当前主会话后续派活的默认值。切换 worker 后，主对话在原会话中继续。主控通过现有 MCP 合同提交所选 `profile_id`，Daemon 校验档案授权和可用性。所选 worker 不可用时，TUI 显示原因，由用户决定是否切换。
- **新任务与续做。** 每次派给 Codex 的任务默认新开 thread，主控在任务书中附上相关的历史 Diff 和验证结果。用户明确要求续做上一单时，可以用 `thread/resume` 恢复同一项目内已结束且可恢复的 Codex 对话，并选用其他 worker 模型。新任务的 worktree 始终从本次选定的代码基线创建。例如，要让 Astra 接着修改 Sol 尚未应用的补丁，可以先用 `/apply` 应用补丁，再从当前工作区拍快照派活。
- **终端内进度和审批。** 任务条显示状态、耗时和改动文件数。遇到危险或越界操作时，用户用键盘选择允许一次、拒绝或取消。主控可以解释申请原因，批准由用户完成。
- **基于实际证据汇报结果。** 主控读取任务 Diff 和验证记录，用中文说明改了什么、哪些检查有运行证据、哪些还待验证。

## 4. 应用与丢弃结果

| 命令 | 行为 |
| --- | --- |
| `/diff` | 在终端查看本次任务相对基线的增量补丁 |
| `/apply` | 先对整份补丁做冲突预检，全部通过后应用到当前工作区，保留暂存区和提交历史。有冲突时主工作区保持原样，列出冲突文件并保留候选 worktree |
| `/discard` | 一次确认后删除候选 worktree，保留任务历史和已保存的 Diff/Patch |

增量补丁用 `git diff --binary --full-index` 生成，支持二进制和新文件。应用时在目标工作区依次运行 `git apply --check` 和 `git apply`，保持整份补丁处理和暂存区原状。

应用状态和验收状态独立记录。整份补丁通过预检后，Daemon 先记录应用意图，再执行实际写入。写入成功后持久化 `applied_at`，再次调用 `/apply` 返回「已应用」。若 Daemon 在写入期间或成功写入后、记录成功前退出，重启后将该次应用标为待确认，保留候选 worktree 供用户核对。

`/apply` 成功后自动走与 `/discard` 相同的清理逻辑。发现任务结束后新增的改动或尚未归档的内容时，保留候选 worktree 并列出路径。清理失败时，已应用的补丁仍留在主工作区。Daemon 异常退出后，按现有规则对账并保留写任务现场，避免重复执行。

## 5. 落地顺序

1. **打通本地入口。** 实现首次零配置启动、`owner.sock`、`/web` 一键登录和动态项目。AGY 使用真实 `HOME`，通过 `--gemini-dir` 隔离设置。Codex 以 `0.166.0` 为最低版本，检查实际能力并记录实际版本，模型目录支持按需刷新。验证同名仓库可并存，同一仓库重复打开复用原项目。
2. **跑通终端主流程。** 实现 AGY 只读项目工具、流式对话、`/model`、`/worker` 和任务条。在同一主会话连续两轮核对 AGY 原始返回值与落库值，确认计数是单轮值还是会话累计值，以及 `inputTokens` 是否已包含缓存读取量。用包含未提交修改和新文件的仓库验证只在实际派活时拍快照、同轮并行任务复用基线，以及键盘审批。
3. **验证结果处理和恢复。** 验证文本、二进制和新文件均可应用，冲突时主工作区保持原样，重复应用返回「已应用」。在 Git 写入后、SQLite 记录成功前强杀 Daemon，验证重启后应用待确认，写任务和补丁均不会自动重放。验证候选被手工修改后拒绝清理。让一个任务等待审阅，确认并行任务使用另一条路径。清理前一个任务并让新任务复用其路径后，再次清理旧任务应保留新任务的 worktree。同步回归两个官方 MCP 入口的派活和结果查询。
